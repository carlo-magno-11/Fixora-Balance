# Security Policy — Fixora Balance

Fixora Balance takes the security and privacy of users seriously.

## Supported versions

Until the first public release, there are no production versions covered by a formal security support window. Once releases begin, supported versions and end-of-support dates will be listed here.

## Reporting a vulnerability

Please do not publish suspected vulnerabilities, exploit details, credentials, personal data, or proof-of-concept attacks in public Issues or Discussions.

If GitHub Private Vulnerability Reporting is enabled for this repository, use the repository's **Security → Advisories → Report a vulnerability** flow.

If private reporting is not available, contact the repository owner privately through the contact method shown on the GitHub profile for carlo-magno-11. Do not include real user data or live credentials in the first report.

Please include:
- A concise description and affected component/version.
- Preconditions and reproducible steps using test data.
- Potential impact and severity rationale.
- A suggested mitigation, if known.

We will acknowledge reports as soon as reasonably possible, investigate in good faith, and coordinate disclosure after a fix or mitigation is available. Please allow reasonable time for investigation and do not access, alter, or exfiltrate other people's data.

## Scope and principles

- Do not test against real users, production accounts, or third-party systems without authorization.
- Do not submit secrets, private keys, payment credentials, or personal/child data.
- Security reports are not a request for compensation; no bug bounty is currently offered.
- This policy does not grant permission to perform testing that would otherwise be unlawful or unauthorized.
